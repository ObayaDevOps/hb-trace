# Worker instructions

Work on the single assigned task. Read its printed briefing, then inspect the named code symbols incrementally. Do not read all plans, tasks, screenshots, manifests or previous conversations.

The coordinator supplies a dispatch record with accepted prerequisite interfaces, relevant decision excerpts, allowed files and fingerprints. A generated briefing alone is not authorization to skip unresolved prerequisites. Tasks start planned; none is claimed implemented by these documents.

## Essential rules

- Domain rules live in `src/domain/`; server adapters/services in `src/server/`; routes in `src/app/`. Browser code must not import server code.
- Server commands own authorization, quantities, quality, committed history, sync results and publication. Never turn hosted failures into fixture-backed success.
- Preserve local mode without provider credentials. Use synthetic data only; never include secrets or production records in prompts or fixtures.
- Use batch/lot terminology. Preserve stable application identities, exact decimal values, immutable sent envelopes and original evidence.
- Public output must exclude private contact, payment, identity, location and staff fields.
- Reference navigation may show later increments. Show only enabled, authorized actions from accepted feature contracts; do not promise an unfinished wax, infusion, messaging or story workflow.
- Keep existing unrelated worktree edits. No deployment, provider activation or applied migration is implied by a code task.

## Working rhythm

Finish a coherent change before checking it. Use an existing focused check or a brief manual main-flow check, plus a critical rejection case where relevant. Do not run tests after every edit, a full suite per task, or the gallery-wide browser script for one screen.

Do not add exhaustive test matrices, snapshots or tests that only repeat implementation. Add a small regression for a demonstrated defect or core invariant. The coordinator owns milestone typecheck/test/build runs; increment 28 owns comprehensive validation.

If required context is missing, report the exact missing interface, rule or dependency. Expand reading only as needed; request coordinator scope review before changing shared contracts or unrelated files. Never omit a correctness rule to fit the context budget.

## Handoff

Write the assigned task result using [the result template](state/tasks/TEMPLATE.md). Include changed paths, exact client-safe exports/contracts, requirement dispositions, focused check evidence, important unverified behavior and blockers. Keep raw logs outside the concise handoff.

Do not mark your own work accepted. The coordinator reviews the diff, dependency impact and evidence. A smoke check establishes only the behavior exercised, not hosted or pilot readiness.
