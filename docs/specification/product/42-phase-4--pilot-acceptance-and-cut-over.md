# Phase 4 — Pilot acceptance and cut-over

Status: authoritative extracted specification; target behavior, not implementation evidence.
Source: [HB-TRACE-V1-PLAN.md — Phase 4 — Pilot acceptance and cut-over](../../../HB-TRACE-V1-PLAN.md#phase-4--pilot-acceptance-and-cut-over)

<a id="prd-42-01"></a>
<!-- requirement:PRD-42-01 -->
- Import agreed data, train staff and conduct a supervised parallel run over at least one complete operating cycle.
<!-- /requirement:PRD-42-01 -->

<a id="prd-42-02"></a>
<!-- requirement:PRD-42-02 -->
- Run restore, recall, permissions, malicious/invalid asset, offline recovery, concurrency, performance, supported
  browser/printer and provider-outage exercises against release-candidate code.
<!-- /requirement:PRD-42-02 -->

<a id="prd-42-03"></a>
<!-- requirement:PRD-42-03 -->
- Prove the complete installed-PWA journey on actual Android and iPhone/iPad devices, including installation,
  standalone navigation, cold offline restart, pending-work upgrades, account switching and the selected printers.
<!-- /requirement:PRD-42-03 -->

<a id="prd-42-04"></a>
<!-- requirement:PRD-42-04 -->
- Resolve all critical/high security issues and every silent-loss, duplicate-allocation or privacy defect before
  go-live; explicitly accept lesser exceptions with owner and deadline.
<!-- /requirement:PRD-42-04 -->

<a id="prd-42-05"></a>
<!-- requirement:PRD-42-05 -->
- Complete operational runbooks, release metadata, support/escalation, RPO/RTO evidence and rollback/cut-over
  approval. Hardening remains a gate in every earlier phase, not work postponed to this phase.
<!-- /requirement:PRD-42-05 -->
